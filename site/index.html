Three conferences publish much of the new research on how chips and computers are designed, checked and built. This atlas sorts 582 of their papers by the problem each one tackles, and explains each problem in plain words.

The common thread

Design is becoming a loop: measure, learn, decide, recheck

Many papers feed a check, a measurement or a physical limit back into the next design choice. The fair question is what each turn of the loop costs.

Why data movement matters

More arithmetic units help only when the data arrives in time

An accelerator is a chip built to do one kind of work fast. Its compute units sit idle when memory cannot feed them.

Where the papers go

What to watch

Six directions, each a hypothesis with a stated test

None is proven. Each page names the paper that pushes back and the result that would disprove it.

1Requirements checked while designingA candidate is useful only when executable constraints can reject, repair, or rank it.2Moving data is the real costUseful computation is constrained by where data is, how far it moves, and what competes for the path.3Measure, then decide the next designA design loop is only useful when sensing cost, model error, decision latency, and update semantics are explicit.4Plan for faults and attacks earlyPerformance without a declared fault and threat operating envelope is not a complete system result.5Heat, wires and power in the loopAn abstract optimum is irrelevant when the physical system cannot realize it.6Better ways to measure resultsEvery result is a measurement with a task population, evaluator, result, uncertainty, and failure boundary.
