Computing where values are stored does not specify how arithmetic works

Compute-in-memory places some calculation within or immediately around a memory structure. Its purpose is to reduce repeated movement of stored values to a separate arithmetic unit.

The calculation can be analog, digital, or a mixture. A memory technology alone does not determine which of these descriptions is correct.

This selected subject contains four records, including a digital lookup-table architecture that does not fit a strictly analog label. It remains here to preserve the existing coding and its review links, but its mechanism is identified correctly below.

The grouping should not be treated as proof that all four papers use analog multiplication or share the same sources of numerical error.

How conductance can implement a weighted sum

In an ideal resistive element, current equals conductance multiplied by applied voltage: I = G × V. If voltages represent inputs and conductances represent weights, currents collected from several elements can represent a sum of products.

This is an elementary circuit model, not an assertion that every paper below implements this exact arrangement.

The useful output is still a number with a required accuracy. The system must encode the inputs as physical signals, allow the circuit to settle, and interpret the output.

A digital-to-analog converter creates a signal from a digital value; an analog-to-digital converter turns a measured signal into a digital value. Their work, along with sensing and control, belongs in the system cost.

If actual conductance is G + ΔG, the idealized product changes by ΔG × V. Across an array, errors may accumulate or partly cancel depending on their signs and correlations.

Wire resistance, noise, nonlinear response, and finite sensing range add other effects. Quantization introduces a different error by restricting numbers to a finite set.

Neither device variation nor quantization (storing numbers with fewer bits) should be described merely as a universal percentage loss independent of the workload.

RM-CIMA: analog control speed matters only if the closed loop remains stable and safe

RM-CIMA combines reinforcement learning with model predictive control and maps learning and optimization into analog computation. The official description reports 7.9× faster recovery from strong wind than nonlinear model predictive control, plus 2995.6× lower computational latency (the wait for one result) and 983.1× lower computational energy than unspecified traditional architectures.

It does not provide absolute times, wind conditions, hardware settings, or measurement boundaries. Recovery of vehicle motion is distinct from computation time; these three factors cannot be multiplied into one gain. Official DAC description.

Model predictive control repeatedly predicts future behavior, chooses an action over a finite planning interval, applies an action, and updates the calculation using new observations. Reinforcement learning adjusts behavior using experience and an objective.

Coupling the two introduces learning costs and questions about how updates change the controller.

Faster computation can allow action on more recent state, but does not establish stability or safe behavior under every disturbance. A proper control evaluation must include sensor and actuator delays, the model's prediction error, update deadlines, and the conditions under which the controller's assumptions fail.

For online learning, memory-write cost and the effect of changing parameters also matter. These are required evaluation dimensions, not recovered RM-CIMA guarantees.

The first gate is closed-loop control validity. Define the vehicle dynamics, MPC horizon, RL (reinforcement learning: learning by trial, from rewards) objective and update rule, wind disturbance, sensor and actuator delays, saturation, constraints and safety policy.

Compare exact versus analog-computed controller outputs and measure trajectory error, overshoot, settling/recovery time, control effort, constraint violations and failure rate across disturbance profiles and random seeds. A shorter arithmetic latency can still produce an unsafe action if the state is stale, the model is wrong or the analog result crosses a control threshold.

The second gate is analog-system accounting. Analog CIM (compute in memory: arithmetic done inside the memory array) computation can be affected by device variation, noise, nonlinearity, drift, finite precision, array parasitics, ADC (analog-to-digital converter: turns a voltage into a number)/DAC conversion, sensing, accumulation, calibration and parameter-write cost.

Compare the complete state-to-actuation path with a matched digital NMPC baseline (the existing method a new result is compared against) at equal tracking quality, including state acquisition, conversions, memory/programming, controller interface, idle power and safety monitoring. Computational energy is not automatically UAV energy, and recovery time is not the same metric as controller latency.

The official description reports 7.9× faster recovery from strong wind than traditional NMPC, 2995.6× lower computational latency and 983.1× lower computational energy than traditional architectures. The captured evidence does not expose absolute times, wind conditions, tracking metrics, controller details, device/peripheral conditions, calibration, closed-loop stability or complete UAV energy.

It supports an analog-CIM RL/MPC control co-design direction, not demonstrated robust UAV flight performance or complete system efficiency.

3D-VRRAM LUT-CiM: low precision makes table-based computation practical

A lookup table stores answers or intermediate results indexed by discrete inputs. With b independent address bits, a complete table can require 2^b entries.

This simple counting relation explains why reducing bit width can reduce table cost much faster than reducing it by one bit might suggest. Partitioned tables and shared intermediate results alter the implementation details, but still require a clear accounting of lookup, combination, and storage work.

The 3D-VRRAM/G-shuffle paper describes digital LUT (look-up table: a small memory that stores a function's answers) computation with four-bit activations and channel-structured four-, two-, and one-bit weights. It combines quantization, reconfigurable computation modes, and physical remapping.

The official description's maximum 8.9× area-efficiency and 9.7× energy-efficiency comparisons are not evidence that all operations use four-bit weights or that computation is analog. Official DAC description.

The author-uploaded manuscript's Sections 4.1–4.2 and Table 2 identify SegFormer-B2: ADE20K segmentation changes from 34.4 to 43.6 mIoU versus round-to-nearest quantization, while NYUDv2 depth error changes from 0.73 to 0.51 RMSE. Full-precision results are 46.3 and 0.47.

Thus the gains are over a quantized baseline, not over full precision.

Section 4.1.2 models the system at 28 nm, 0.9 V, and 400 MHz using silicon-derived VRRAM data and synthesized/simulated supporting circuits. Table 3 uses one prior result from a different language-model workload and another normalized for vision.

Those comparisons are not all matched end-to-end measurements. Author-uploaded manuscript, Sections 4.1–4.2 and Tables 1–3.

3D-VRRAM LUT-CiM: a better 4-bit quantizer still has to survive the memory array and the complete edge path

Dense prediction produces a structured output at many image locations, so the useful quality constraint is task-specific: segmentation must preserve regions and classes, while depth estimation must preserve metric relationships and numerical error. A low-bit ViT can reduce storage and arithmetic, but lookup-table cost, mixed precision, activation movement and analog/memory nonidealities all determine whether the model is actually deployable.

The software side of the proposal uses Greedy G-Shuffle quantization and PCA-based channel-wise weight assignment to produce structured INT4/2/1 weights with INT4 activations. The hardware side uses a reconfigurable LUT-based CiM macro, pipeline/tensor-parallel dataflow, flexible 1TnR VRRAM read paths and channel-wise remapping so different ViT layers can use different precision and computation modes.

The co-design addresses a real mismatch between heterogeneous layer workloads and a fixed LUT. It does not imply that a quantized model is full-precision equivalent or that a mode-reconfigurable macro has no switching, sensing, calibration or data-movement cost.

The first gate is model and device fidelity. Compare full precision, vanilla round-to-nearest and Greedy G-Shuffle at layer outputs and final dense-prediction outputs.

Then inject VRRAM variation, drift, read noise, conductance nonlinearity, IR drop (the fall in supply voltage along the chip's power wires), ADC/sensing quantization, accumulation error and calibration residuals. Report per-layer error, mIoU/RMSE distributions, class or depth failure cases, temperature/voltage corners and whether INT4/2/1 remapping changes the error pattern.

The manuscript's mIoU and RMSE improvements over round-to-nearest are quantization-baseline results; they do not establish equality with full precision.

The second gate is the complete macro accounting. LUT storage and lookup, remapping, read paths, ADC/DAC, accumulation, buffers, controllers, pipeline fill, tensor-parallel synchronization, mode selection, programming, calibration and reconfiguration must be included in area, energy and latency.

State which values are measured silicon, silicon-derived device data, circuit simulation, synthesis or extrapolation. A normalized prior result from another workload or a vision-adjusted comparison cannot be treated as a matched end-to-end accelerator (a chip or block built to do one kind of work fast) baseline.

The third gate is edge-system validity. Evaluate the entire model—including unsupported or non-LUT layers, preprocessing, feature movement, host/controller interaction, reconfiguration and output handling—on named hardware and a stated batch/latency target.

Hold the dataset, resolution, model, precision, quality threshold, process, voltage, frequency and peripheral boundary constant against a digital 4-bit accelerator and fixed VRRAM-CiM design. Measure sustained latency, throughput (how much work is finished per second), energy, area, memory capacity, temperature, calibration frequency, endurance and failure behavior rather than only a macro ratio.

The manuscript reports SegFormer-B2 mIoU of 43.6 versus 34.4 for vanilla round-to-nearest and 46.3 full precision on ADE20K, NYUDv2 RMSE of 0.51 versus 0.73 and 0.47 full precision, and a 28-nm/0.9-V/400-MHz modeled evaluation using silicon-derived VRRAM data and synthesized/simulated support circuits. It claims up to 8.9× area efficiency and 9.7× energy efficiency, but Table 3 includes normalized or differently scoped prior comparisons.

The evidence supports low-precision reconfigurable VRRAM LUT-CiM co-design, not demonstrated universal 4-bit ViT edge deployment efficiency or fabricated endurance.

Dense prediction produces outputs across an image rather than a single image label. Mean intersection-over-union, or mIoU, compares predicted and reference regions and averages the overlap measure across classes.

Root mean square error, or RMSE, summarizes numerical prediction errors, with larger errors weighted more strongly before taking the square root. Higher mIoU and lower RMSE are desirable, but they are not interchangeable accuracy percentages.

SDM: a smooth decision changes sensitivity, not the need for validation

SDM transforms a multivariable model into a univariate form and uses a one-ferroelectric-transistor analog content-addressable memory to compute a sigmoid. Its description reports 93.2% MNIST accuracy under 40 mV device variation, with a 0.54% drop versus 43.86% and 16.06% drops for decision-tree and random-forest comparisons.

It does not define the variation distribution, percentage conventions, baseline hardware, or whether these outcomes were measured on fabricated circuits. Official DAC description.

A hard decision switches branches when an input crosses a threshold. A sigmoid changes smoothly between low and high values.

Near a hard threshold, a small perturbation can reverse the branch choice. A smooth function instead changes its output gradually, although its sensitivity still depends on slope and on how subsequent computation uses that value.

Content-addressable memory searches stored entries by their content rather than solely by an explicit address. An analog version can implement a graded matching response.

A ferroelectric transistor uses a persistent polarization state to influence electrical behavior. Neither description establishes that every cell has identical response or that classification remains robust outside the tested conditions.

Smoothness is a mechanism to examine, not a blanket immunity to variation.

SDM: a soft decision can reduce threshold sensitivity, but variation, calibration and system cost still need measurement

A hard decision changes branches when an input crosses a threshold. That discontinuity makes a small device-induced shift capable of changing the selected branch.

A sigmoid instead maps a scalar to a gradual value between low and high limits. This can make the output less abrupt near a boundary, but the slope, saturation, input scaling and later thresholding determine how much a voltage or conductance error changes the final class.

Softness is therefore a circuit/algorithm co-design choice, not a proof of variation immunity.

SDM is described as transforming a multivariate interpretable model into a hardware-friendly univariate form and implementing the required sigmoid in a compact one-ferroelectric-transistor (1-FeFET) analog content-addressable memory (CAM). The CAM's analog response is used for a soft decision rather than a purely digital branch.

The captured description does not specify the feature transform, stored parameters, CAM match/sense path, sigmoid transfer curve, ADC or peripheral circuitry, precision, calibration, or how multiple univariate decisions are combined. Those details determine whether the physical response corresponds to the intended model.

The first gate is device-to-model fidelity. Characterize the mapping from FeFET state and input voltage to the sensed analog output, then compare it with a numerical sigmoid over the full operating range.

Report slope and saturation error, noise, quantization, input-scaling error, decision-boundary shifts, probability calibration and false-positive/false-negative behavior. Compare model outputs and MNIST predictions with a trusted digital reference.

A smooth analog curve can still be systematically biased or miscalibrated.

The second gate is variation robustness. Define whether 40 mV means device-to-device threshold variation, temporal drift, spatially correlated variation or another quantity; state the distribution, number of instances, temperature/voltage conditions, aging, noise and whether parameters were retrained or calibrated for each instance.

Evaluate fixed parameters on held-out device samples and report mean, worst-case and tail accuracy, accuracy confidence intervals, output error and calibration/retraining/storage cost. Separate inherent tolerance from compensation that consumes area, energy or test time.

The task comparison must also preserve its denominator. Identify the clean reference accuracy and whether the reported 0.54%, 43.86% and 16.06% values are absolute percentage-point drops or relative percentages, and inject variation at the same model/hardware boundary for SDM, decision tree and random forest.

Measure feature preparation, CAM lookup, sensing, ADC/DAC, control, output transfer, latency, energy and area at matched MNIST quality and precision. A robustness percentage alone does not establish edge efficiency or preserved interpretability.

The official description reports 93.2% MNIST accuracy under 40 mV device variation, with a 0.54% drop for SDM versus reported 43.86% and 16.06% drops for decision-tree and random-forest comparisons. It does not expose absolute baseline accuracy, variation statistics, circuit conditions, calibration, sigmoid error, latency, energy, area, sample count or fabricated-silicon evidence.

The evidence supports a soft-decision analog-CIM direction, not demonstrated calibrated, process-robust or end-to-end edge efficiency.

HP-CIM: attention sparsity helps only when Top-K errors and ReRAM cost remain bounded

Attention compares a query with many keys, then uses normalized scores to weight the corresponding values. A sparse accelerator tries to keep only the important keys, reducing arithmetic and movement.

The selection itself is part of the cost, however, and its errors are asymmetric: retaining an unimportant key wastes work, while discarding an important key changes the weighted sum and can affect every later layer.

HP-CIM is described as a hybrid ReRAM–SRAM (small, fast memory built on the chip itself) computing-in-memory transformer accelerator. Its ReRAM-based hash predictor (ReHP) uses device variability for low-cost projections; a ReRAM content-addressable match and K-winner-take-all circuit select Top-K query-key candidates; an optimizable bias-softmax mechanism compensates information loss.

These mechanisms move approximate projection and selection toward memory. They do not establish that the selected set matches dense attention, that device variability is stable, or that compensation recovers omitted information.

Hash encoding, K/sparsity, thresholds, precision, calibration and controller behavior are not specified in the captured description.

The first gate is attention and model fidelity. Define the dense reference, Top-K rule, hash collisions, score threshold, K by layer/head, sequence length and precision.

Report selected-edge recall and false-negative/false-positive rates, attention/logit error, perplexity or task quality, long-context behavior and per-layer failure cases against dense attention under matched prompts, seeds or decoding. A good average task score can hide a head or layer whose dropped key causes a rare but important failure; “bias-softmax compensation” is not proof of exact recovery.

The second gate is device-to-system validity. Characterize ReRAM conductance variation, noise, drift, nonlinearity, temperature, voltage, aging and read conditions through the projection, CAM match and K-WTA path.

Include ADC/DAC, sensing, calibration, SRAM, buffers, digital control, hash metadata, data movement, unsupported layers and retries in latency, energy and area. Report fixed-parameter held-out devices separately from per-device calibration; exploiting variation does not make variation free.

Compare dense transformer acceleration, software sparsification and prior CIM accelerators at the same model, task, precision, sequence length, batch, quality target, technology, peripheral inclusion and end-to-end boundary. Measure Top-K selection, bias-softmax, memory transfers, setup, sustained p50/p95/p99 latency, energy/token, TOPS/W definition, area, thermal behavior and endurance.

The official description reports 9.05–310.04× energy-efficiency improvement and 2.48–16.93× speedups across diverse tasks, but provides no accuracy, attention recall, absolute latency/energy, area, variation, ADC/DAC, endurance or per-model conditions. The evidence supports ReRAM-assisted attention sparsity and hybrid CIM, not demonstrated quality-preserving, variation-robust or fabricated-system transformer efficiency.

HP-CIM: deciding what to skip must cost less than the work skipped

HP-CIM combines ReRAM and SRAM computation with a ReRAM hash predictor. The description uses device variation for projections, content-addressable matching and a K-winner selection circuit, plus an adjustable bias-softmax mechanism to compensate information loss.

It reports 9.05–310.04× energy efficiency and 2.48–16.93× speedups against prior CIM transformer accelerators. Model conditions, accuracy outcomes, comparator identities, and physical measurement scope remain unspecified.

These ranges cannot be assigned to every workload or interpreted as fabricated-system measurements. Official DAC description.

In attention, a query is compared with keys to determine how much information to use from different positions. A hash predictor replaces an expensive comparison with a compact representation intended to retain useful similarity.

This is not a cryptographic guarantee. Selecting K candidates means retaining a fixed number according to the predictor's ranking, not proving that every discarded contribution is irrelevant.

Two error directions have different costs. Retaining an unimportant candidate wastes computation; discarding an important one can change the result.

Softmax converts scores into normalized weights, so changing which scores are represented can affect the whole weighted combination. A compensating bias may improve task quality, but its name alone does not establish exact recovery of omitted information.

What the four cases imply about system comparisons

These proposals target control-loop computation, discrete table arithmetic, nonlinear matching, and sparse-attention selection. Their shared question is whether performing a particular operation near stored state saves enough movement to justify encoding, sensing, selection, programming, and control costs.

A credible comparison keeps task quality and the timing boundary explicit. Circuit energy per operation cannot stand in for total vehicle energy, and peak arithmetic efficiency cannot establish application throughput.

Calibration and programming may be occasional rather than per-operation costs, but should be amortized over a stated use period rather than omitted.

The author-uploaded LUT manuscript is available as extracted text with section and table locations; the separate PDF download failed, so exact PDF-page mapping remains unverified. Full manuscripts for the other three records were not recovered.

The refreshed evidence supersedes historical card omissions, but device-to-task validation, taxonomy reconciliation, and independent reproduction remain open. These four mechanisms support a comparison, not a demonstrated long-term prevalence trend.

Compare the results carefully

How to compare these papers’ results fairly

First identify the inputs and required output quality. Then identify the limited resource: time, memory, communication, energy, circuit area, or correctness coverage.

Ask which part of the method reduces that cost and which new cost it adds. Compare numbers only when the experiments hold these conditions sufficiently similar.

Correction register

Problem:

Decision trees and random forests can be costly or difficult to map to edge hardware, while analog in-memory nonlinear decisions are sensitive to device variation and a digital sigmoid implementation can require data movement and peripheral computation.

Mechanism / artifact:

Limits on the conclusion:

A smooth sigmoid can reduce the discontinuity of a hard branch, but it is not automatically calibrated or variation-invariant. Define the device-to-sigmoid transfer, slope and saturation, input scaling, sensing/readout, quantization, noise and calibration; compare analog outputs with a numerical sigmoid and report approximation error, probability calibration, decision-boundary shifts, false positives/negatives and accuracy across held-out device instances.

A nominal curve fit does not establish robust model behavior.

The 40 mV condition needs a distribution and physical interpretation: device-to-device versus temporal variation, spatial correlation, temperature/voltage dependence, measured versus modeled samples, worst-case/tail behavior and whether the model was retrained or recalibrated under variation. Evaluate unseen variation, aging, noise and operating corners with fixed parameters, and separate algorithmic robustness from compensation or retraining cost.

The DT/RF percentage drops must identify the clean reference, absolute accuracy, variation injection point and hardware/model boundary. Compare SDM, DT and RF at matched task quality, feature computation, memory capacity, precision, inference latency, energy and area; a robustness percentage alone does not show that SDM is more efficient or that the transformed model remains interpretable.

Include feature transforms, CAM lookup, sensing, ADC/DAC, control and output transfer in edge-system measurements.

Correction register

Problem:

Transformer attention compares many query-key pairs, making dense computation and memory movement expensive; sparsifying attention can save work but identifying the top keys itself costs hardware resources or can remove information needed for model quality.

Mechanism / artifact:

HP-CIM is described as a hybrid ReRAM–SRAM CIM transformer accelerator with a ReRAM-based hash predictor (ReHP) that uses device variability for low-cost projections, ReRAM CAM matching and a K-winner-take-all circuit for Top-K selection, plus an optimizable bias-softmax mechanism to compensate information loss; hash encoding, K/threshold, analog precision, calibration, ADC/DAC, mapping, controller and compensation training are unspecified.

Hardware and manufacturing assumptions:

Reported measurements:

The official description reports 9.05–310.04x energy-efficiency improvement and 2.48–16.93x speedups over state-of-the-art CIM-based transformer accelerators across diverse tasks, but does not report accuracy/perplexity, attention recall, absolute latency/energy, TOPS/W definition, area, variation, ADC/DAC cost, endurance or per-model/task conditions.

Limits on the conclusion:

Top-K prediction has asymmetric errors: retaining an unimportant key wastes work, while dropping an important key changes the weighted sum and can propagate through layers. Define the exact attention reference, K/sparsity, hash collision behavior, score threshold, false-negative/false-positive rate, head/layer distribution and compare logits, perplexity/task quality and long-context tails with dense attention.

Bias-softmax compensation is not proof of recovered information.

ReRAM variability is part of the predictor and also a source of drift, noise, nonlinearity and device-to-device mismatch. Characterize the projection/CAM/K-WTA path across conductance distributions, temperature, voltage, aging and read conditions; include ADC/DAC, sensing, calibration, digital control, SRAM, buffers, data movement and failure/retry in area, latency and energy.

Report fixed-parameter held-out devices and calibration cost separately.

The headline ranges need model, task, sparsity, precision, batch, baseline and measurement boundaries. Compare dense and sparsified paths at matched quality, and include hash projection, Top-K selection, bias-softmax, unsupported layers, memory transfers, setup and output handling.

Measure sustained inference, p50/p95/p99 latency, energy/token, area, thermal behavior and endurance. The evidence supports ReRAM-assisted attention sparsity and hybrid CIM, not demonstrated quality-preserving, variation-robust or fabricated-system transformer efficiency.
